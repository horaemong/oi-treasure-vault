﻿# 전역 프로젝트 루틴 전달 프롬프트

연결: 유튜브 Project Start Routine

기존 프로젝트 또는 별도 Codex 프로젝트 스레드에 아래 프롬프트를 그대로 전달한다.

이 프로젝트를 내 전역 프로젝트 운영 루틴에 편입해줘.

반드시 먼저 아래 전역 기준을 읽고 따른다:
- `C:\Users\user\.codex\skills\project-start-routine\SKILL.md`
- `C:\Users\user\.codex\skills\workspace-obsidian-memory\SKILL.md`
- `C:\Users\user\.codex\skills\project-git-handoff\SKILL.md`
- `C:\Users\user\.codex\skills\work-progress-daily-log\SKILL.md`
- 가능하면 `G:\내 드라이브\obsidian\para\_system\project-start-routine.md`도 확인한다.

중요: 이 프로젝트 안에서만 따로 기록하고 끝내지 마라. 이 프로젝트를 전역 시스템에 연결해야 한다.

해야 할 일:
1. 현재 프로젝트 폴더와 목적을 확인한다.
2. 관련된 Obsidian 공개 기억 위치를 찾거나 제안한다.
3. 이 프로젝트에서 공개 Obsidian에 남길 내용과 private/local로 분리할 내용을 구분한다.
4. 프로젝트 안에 `docs/worklog/YYYY-MM-DD.md`를 만들거나 갱신한다.
5. 필요하면 `진행사항/YYYY-MM-DD.md`도 만들거나 갱신한다.
6. Git 저장소라면 `git status`를 확인하고, 커밋/푸시는 내가 명시적으로 승인하기 전에는 하지 않는다.
7. `G:\내 드라이브\obsidian\para\_system\workspace-project-map.md` 또는 적절한 Obsidian 공개 노트와 연결해야 할 항목을 보고한다. 쓰기 권한이 있으면 직접 갱신하고, 권한이 없으면 정확한 갱신 문구를 제시한다.
8. 마지막 답변에는 반드시 아래 형식으로 보고한다.

보고 형식:
- 작업 폴더:
- 공개 Obsidian 기록 위치:
- private/local 기록 위치:
- 생성/갱신한 project worklog:
- 생성/갱신한 진행사항:
- Git 상태:
- 다음에 이 프로젝트를 이어갈 때 먼저 볼 파일:
- Obsidian이나 전역 시스템에 반영하지 못한 항목:
