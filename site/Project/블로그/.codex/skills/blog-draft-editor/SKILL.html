Blog Draft Editor

This skill is local to this blog project. It is for editing the user's existing draft posts, not for creating generic articles from scratch.

Core Workflow

  1. Locate and read the target draft first.
  • Default draft folder: 0. 초안
  • If the user names a post, find the matching Markdown file before editing.
  • Do not invent a new article when an existing draft is available.
  1. Rewrite directly into blog-post form.
  • The user usually brings most of the raw material.
  • Do not stop at an outline unless the user explicitly asks for one.
  • Convert the draft into a readable post with a clear title, opening hook, section flow, and conclusion.
  1. Overwrite the existing file.
  • The default edit mode is direct overwrite of the target draft file.
  • Do not create 정리본, 수정본, or duplicate files unless the user asks for a separate version.
  • Read the current file before overwriting.
  1. Verify after saving.
  • Re-read the beginning of the saved file to confirm the edit landed.
  • Mention the edited file path in the final response.

Voice And Tone

Preserve the user's natural blog voice:

  • Sharp, direct, and unsentimental.
  • Analysis-driven rather than purely emotional.
  • Uses strong metaphors, but should still land in a practical conclusion.
  • Prefers "wake up and look at reality" energy over soft comfort.
  • Comfortable with blunt phrases when they sharpen the point.
  • Ends by pushing the reader toward action, judgment, self-objectification, or clearer thinking.

The tone should usually be:

  • Strong but readable.
  • Critical but structured.
  • Fierce but not messy.
  • Persuasive rather than merely angry.
  • More like a field report or tactical diagnosis than a diary rant.

Editing Rules

  • Keep the user's main claim, emotional pressure, and memorable phrases whenever possible.
  • Strengthen structure before polishing sentences.
  • Turn scattered thoughts into a clear sequence:
  • opening hook
  • problem definition
  • core analysis
  • examples or mechanisms
  • conclusion with a decisive takeaway
  • Use short paragraphs for blog readability.
  • Use numbered sections when the argument has multiple mechanisms or steps.
  • Keep Markdown formatting clean.
  • Remove accidental assistant chatter, meta comments, and leftover drafting notes unless they are useful to the post.
  • Preserve image placement notes if they help publishing, but clean their wording.

Default Structure

For most posts, use this shape unless the draft clearly calls for another:

# Title

Opening hook.

Problem framing.

---

## 1. First Core Point

Body.

## 2. Second Core Point

Body.

## 3. Third Core Point

Body.

## 결론

Final synthesis and action-oriented closing.

Topic-Specific Guidance

For political or social criticism posts:

  • Keep the tactical, structural lens.
  • Separate claims into mechanisms: frame control, agenda narrowing, fake achievements, responsibility shifting, public psychology.
  • Avoid letting anger replace argument.
  • Make the chain of cause and effect explicit.
  • When writing about corruption, immoral profit, or people abandoning conscience, check whether the stronger argument is not only "do not become corrupt" but also "do not enter the corrupt minority's order late."
  • Treat immoral profiteers as a powerful minority, not automatically as the majority.
  • Emphasize that their large gains often look large because fewer people split the spoils.
  • Show that if more people choose corruption, the pool gets crowded, latecomers receive less, and the early profiteers keep the advantage.
  • Frame imitation as surrendering to their rules, not as revenge or realism.
  • Preserve the possibility that the honest majority can beat the corrupt minority, even narrowly, if it recognizes itself and acts together.

For self-development posts:

  • Keep the blunt diagnosis.
  • Use analogies such as debugging, data, warning lights, investment, waste, and feedback loops when they fit.
  • End with a concrete mental model or action.

For personal record posts:

  • Preserve the user's lived experience.
  • Make the lesson visible without flattening the personality.
  • Do not over-polish into corporate essay tone.

Final Response

After editing, answer briefly:

  • Say the file was updated.
  • Name the main improvements.
  • Mention verification if done.
  • Do not paste the whole article unless the user asks.
