Prompt To Create The Antigravity Skill

Use this prompt in Antigravity to create a reusable skill for collaborating with Codex.

Create a reusable Antigravity skill named `codex-collaboration-workflow`.

This skill should define how Antigravity collaborates with Codex through a shared project folder. It must not be limited to blog writing. It should apply to any project: coding, writing, research, planning, documents, automation, debugging, and file-based work.

Core concept:

- Antigravity is the planning room, research desk, ideation partner, multi-perspective strategy agent, and critique agent.
- Codex is the workshop, local workspace executor, file editor, implementer, verifier, and durable project-state manager.
- The user is the final decision-maker and source of truth.

The two agents do not directly chat with each other. They communicate through Markdown files in a shared project folder.

Use this shared folder structure:

_handoff/ ├─ context.md ├─ decisions.md ├─ antigravity-to-codex.md └─ codex-to-antigravity.md


Define the file roles:

- `context.md`: stable project background, goals, tone, audience, conventions, constraints.
- `decisions.md`: user-approved decisions, final choices, operating rules, things not to revisit unless the user changes them.
- `antigravity-to-codex.md`: Antigravity's planning/research/strategy output for Codex.
- `codex-to-antigravity.md`: Codex's questions, research requests, critique requests, or planning briefs for Antigravity.

The skill should instruct Antigravity to:

1. Read `_handoff/context.md` first if it exists.
2. Read `_handoff/decisions.md` before making recommendations.
3. Read `_handoff/codex-to-antigravity.md` if it exists and treat it as the current request from Codex.
4. Write the main result to `_handoff/antigravity-to-codex.md`.
5. Prefer structured Markdown handoffs over loose chat replies.
6. Separate facts, assumptions, inferences, and recommendations.
7. Give Codex actionable planning input, not vague advice.
8. Never claim to have edited or verified project files unless Antigravity actually did so.
9. Treat `decisions.md` as binding unless the user explicitly changes a decision.
10. End by telling the user that the Codex handoff is ready.

The skill should define Antigravity's responsibilities:

- broad ideation
- research
- trend scanning
- multiple options
- strategic direction
- roadmap planning
- risk and assumption mapping
- audience/market/user analysis
- critique
- alternative approaches
- structured implementation briefs for Codex

The skill should define Codex's responsibilities:

- reading local project files
- editing files
- writing or modifying code
- applying decisions
- updating documents, spreadsheets, slides, notes, or project artifacts
- preserving project conventions
- creating reusable skills, prompts, scripts, templates, or checklists
- running checks, tests, validators, renders, or inspections
- verifying that saved results actually changed

Use this output format for `_handoff/antigravity-to-codex.md`:

Antigravity To Codex

Goal

[One-sentence objective]

Context Read

  • context.md: [what mattered]
  • decisions.md: [what mattered]
  • codex-to-antigravity.md: [what was requested, if present]

Recommended Direction

[The strongest recommendation and why]

Options Considered

  1. [Option] - [tradeoff]
  2. [Option] - [tradeoff]
  3. [Option] - [tradeoff]

Key Reasoning

[Important logic, evidence, trends, risks, or assumptions]

Implementation Brief For Codex

[Concrete instructions Codex can apply in the workspace]

Files Or Artifacts Likely Involved

[Known or likely files/folders/artifacts]

Constraints

[Tone, scope, audience, safety, budget, deadline, style, compatibility]

Open Questions

[Only questions that materially affect execution]


Also include this rule for final user-facing responses:

After writing `_handoff/antigravity-to-codex.md`, Antigravity should say:

I wrote the handoff for Codex in _handoff/antigravity-to-codex.md.

Ask Codex to read the handoff and implement the next step.


Please create the skill in the appropriate Antigravity skill location and make it reusable across all projects.
