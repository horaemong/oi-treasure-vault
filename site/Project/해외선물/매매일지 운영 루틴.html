﻿# 매매일지 운영 루틴

연결: 해외선물 CODE 기록법 블로그

요약

  • 매매일지 리뷰와 주간 매매일지는 Area/100. 일기 안에서 반복 운영한다.
  • 일간 매매일지는 원칙 준수, 감정 개입, 다음 패치를 확인하는 원천 기록이다.
  • 주간 매매일지는 블로그용 공개 기록으로 만들되, 민감한 계좌/전략/원문 감정은 공개하지 않는다.

작업 위치

관련 작업 폴더: G:\내 드라이브\obsidian\para\Area\100. 일기 관련 템플릿: G:\내 드라이브\obsidian\para\Area\100. 일기\주간 매매일지 템플릿.md 프로젝트 worklog: G:\내 드라이브\obsidian\para\Area\100. 일기\docs\worklog\YYYY-MM-DD.md 진행사항: G:\내 드라이브\obsidian\para\Area\100. 일기\진행사항\YYYY-MM-DD.md

운영 방식

  • Daily: 일간 일지의 # 해외선물 또는 매매일지 섹션만 읽고 원칙 준수, 감정 상태, 뇌동매매 가능성, 다음 행동 패치를 평가한다.
  • Weekly: 주간 매매일지 템플릿.md를 복사해 YYYY-W__ 주간 매매일지.md를 만들거나 갱신한다.
  • Weekly classification: 타점 원문은 보존하고, 수익 본 매매 / 손해 본 매매: 신호 / 손해 본 매매: 감정(뇌동 매매)로 분류한다.
  • OI 뉴스레터와 주간 매매일지는 분리한다. 뉴스레터는 관계와 재시작의 이야기이고, 매매일지는 규칙/리스크/심리/패치의 기록이다.

공개 기록과 private/local 분리

공개 Obsidian에 남길 수 있는 것:

  • 매매일지 운영 방식
  • 템플릿 구조
  • 공개 가능한 원칙 변화
  • 블로그용 주간 매매일지 초안
  • 재사용 가능한 복기 기준과 다음 패치

private/local로 분리할 것:

  • 계좌 세부 정보
  • 공개하기 어려운 원문 감정
  • 민감한 개인 재정 맥락
  • 공개 전 원본 수준의 매매 전략
  • 사람/계정/거래 환경 관련 민감 정보

다음에 참고할 것

  • 매매일지를 읽을 때는 trading-journal-review 스킬을 우선 사용한다.
  • 프로젝트 시작/재개 시에는 project-start-routine의 Trading Journal Project Rule을 따른다.
  • Git 저장소가 아니므로 커밋/푸시는 기본 절차가 아니다. 전역 handoff는 Obsidian worklog와 진행사항 파일로 남긴다.
